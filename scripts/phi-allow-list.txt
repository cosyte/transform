# scripts/phi-allow-list.txt
#
# PHI-scan allow-list: the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit. Byte-strict wire formats cannot carry an
# inline `# synthetic: true` header (the header segment must be the first bytes),
# so this allow-list is the synthetic-fixture declaration mechanism: the same
# approach every sibling `@cosyte/*` parser uses.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>          synthetic person-name word, matched case-insensitively
#   DOB <value>           synthetic date of birth, the leading 8 digits of a v2 TS
#   ID <value>            synthetic id matching an SSN / MRN / member-id shape
#   ADDRESS <value>       synthetic address component (street, city, postal code)
#   PHONE <value>         synthetic telephone number, compared on digits only
#   EMAILDOMAIN <domain>  reserved / test email domain that is allowed to appear
#   EMAIL <path> <addr>   one allowed mailbox in one file: the narrowest tag here
#
# ▶ EVERY ENTRY HERE IS ROUTE-BLIND. It clears its literal on the all-mode walk,
#   on `pnpm phi-scan <path>`, AND on `--staged`, which is the pre-commit gate.
#   So adding one is a subtraction from the commit-blocking route as well,
#   whatever the reason for adding it was. There is no route-scoped tag and
#   there should not be: a value that is safe on one route and not another is a
#   claim nobody can hold in their head.
#
# ▶ AND EVERY TAG BUT ONE IS ALSO FILE-BLIND. `NAME`, `DOB`, `ID`, `ADDRESS`,
#   `PHONE` and `EMAILDOMAIN` clear their value in EVERY file the scan reads.
#   `EMAIL` is the exception: it takes a literal path as well, so it clears one
#   address in one file. Prefer the narrowest tag that covers the case.
#
# ▶ NEVER ADD A VALUE THIS REPOSITORY'S OWN GATE TESTS USE AS A TRIPWIRE. The
#   violator payloads in `test/scripts/phi-scan.test.ts` are assembled from
#   parts at runtime precisely so they never need an entry here: allow-listing
#   one would blind the floor for every corpus at once.
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act, never silent.

# --- Allowed mailboxes: one address, in one file ---
#
# ▶ THIS IS NOT A SCRUB, AND THE ADDRESS IS NAMED HERE ON PURPOSE. The one
#   mailbox this repository carries is the npm publisher contact in
#   `package.json`'s `author` field. It is public (it is on the package's
#   registry page), it is an organisation address rather than a person's, and it
#   is not PHI. Deleting it to get the gate green would destroy the evidence
#   that this audit looked at it, which is the opposite of what an audit is for.
#
# ▶ AND ITS COST, STATED RATHER THAN LEFT TO BE FOUND. Two literals, so this is
#   as narrow as this mechanism goes: every OTHER address at cosyte.com still
#   reports, and this SAME address in any other file still reports. What it does
#   cost is one measured cell: before this change `pnpm phi-scan package.json`
#   exited 1 on that mailbox, and now it exits 0. That is a real subtraction, it
#   is the only one in this change, and it is the price of the walk covering
#   package.json at all rather than exempting the whole file.
#   `test/scripts/phi-scan.test.ts` pins the cell and both narrowness halves.
# The declaration itself carries the literal, so the file holding it needs its
# own entry. Stated rather than special-cased in the scanner: an allow-list that
# silently excused itself would be the one file nobody checks.
EMAIL package.json hello@cosyte.com
EMAIL scripts/phi-allow-list.txt hello@cosyte.com

# ===========================================================================
# THE PUBLISHED v2-TO-FHIR TEST CORPUS
# ===========================================================================
#
# WHAT IT IS. `test/_support/ig-corpus/messages.json` carries the seven v2 test
# messages the HL7 Version 2 to FHIR implementation guide publishes on
# https://hl7.org/fhir/uv/v2mappings/test_conversions.html (retrieved
# 2026-09-08, page sha256 a25b317e58c872b8bd21a3dcfb893b00f7fc2d24025dd21a83cef11678642a38).
# They are the guide's own benchmark messages, published openly and freely
# licensed, and every identifier in them is a placeholder the guide invented:
# "Eve Everywoman" is its standing synthetic patient, the addresses are in the
# reserved 99999 postal code or are obvious placeholders, the telephone numbers
# are in the reserved 555 exchange or use an unassignable area code, and the one
# Social Security Number is an all-zero placeholder in area 000, which the
# Social Security Administration has never issued and never will. That value is
# NOT written out anywhere in this file: it is a dashed shape, this scanner
# refuses every dashed shape unconditionally, and a quoted violator here would
# red the gate on every run.
#
# ▶ WHY THE CORPUS IS IN THE WALK AND NOT BESIDE IT. `test` is already a scan
#   root, so these files are read by the same passes as every other fixture, and
#   the gate DOES bite on them: before these entries existed the scan reported
#   over two hundred hits in that one file. `test/scripts/phi-scan-corpus.test.ts`
#   plants an uncovered violator inside the corpus directory and asserts a
#   non-zero exit, so "inside the gate" is measured rather than asserted.
#
# ▶ AND THE COST, STATED RATHER THAN LEFT TO BE FOUND. Every tag below except
#   EMAIL is FILE-blind and all of them are ROUTE-blind, so each one is a real
#   subtraction from this repository's whole PHI gate, pre-commit included. What
#   is bought for it is a corpus nobody has to keep outside the gate. Each value
#   was read by hand before it was declared, and none of them is a value this
#   repository's own gate tests use as a tripwire (those are assembled at runtime
#   in `test/scripts/phi-scan.test.ts` precisely so they never need an entry).
#
# --- The corpus's two mailboxes, path-scoped: the narrowest tag there is ---
#
# Two entries per address, because this file is itself inside the scan corpus
# and the declaration carries the literal. Same shape as the publisher-mailbox
# entries above, and for the same reason.
EMAIL test/_support/ig-corpus/messages.json eve@test.test
EMAIL test/_support/ig-corpus/messages.json me@northpole.earth
EMAIL scripts/phi-allow-list.txt eve@test.test
EMAIL scripts/phi-allow-list.txt me@northpole.earth
